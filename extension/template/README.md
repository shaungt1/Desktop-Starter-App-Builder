# __APP_NAME__

__APP_DESCRIPTION__

This is a Manifest V3 browser extension built with [WXT](https://wxt.dev), React,
Tailwind CSS and TypeScript. It builds for Chrome and Edge (one build) and
Firefox. This project was generated by Desktop Starter App Builder, and it is
self-contained: you do not need the builder to keep working on it.

## Get started

You need Bun and Node.js 22.17 or newer. Check the machine, install the packages
and open the extension in a browser:

```bash
bun run doctor        # checks the tools this project needs (never installs)
bun install
bun run dev           # builds into .output/chrome-mv3-dev and rebuilds on every save
```

If `doctor` reports something missing, `bash scripts/bootstrap.sh --dry-run`
shows what would be installed and `bash scripts/bootstrap.sh` installs it after
asking (on Windows run it in Git Bash). [`docs/SETUP_RESOURCES.md`](docs/SETUP_RESOURCES.md)
lists every tool with manual steps for each operating system.

## Commands

| Command | What it does |
| --- | --- |
| `bun run dev` / `dev:firefox` | Development mode: builds and rebuilds on save for Chrome / Firefox |
| `bun run build` / `build:firefox` | Production build into `.output/chrome-mv3` / `.output/firefox-mv2` |
| `bun run zip` / `zip:firefox` / `zip:all` | Store upload ZIP files in `.output/` |
| `bun run verify` | Type check, lint and format check, unit tests |
| `bun run test:e2e` | Build, then drive the extension in Chromium with Playwright |
| `bun run format` | Fix formatting and import order |

## Folder layout

The list below names what each part is for.

1. `entrypoints/` — what the browser runs: `background.ts` (service worker), `popup/`, `options/` and `content.ts`. WXT turns these files into the manifest.
2. `src/app/` — the popup and options screens (React).
3. `src/components/ui/` — small shared components (button, card, switch).
4. `src/lib/` — typed messaging (`messaging.ts`), saved settings (`settings.ts`) and helpers.
5. `src/modules/` — optional features added with the builder's `module add` command.
6. `tests/unit/` — Vitest tests with an in-memory copy of the browser APIs; `tests/e2e/` — Playwright tests against the built extension.
7. `public/icon/` — toolbar and store icons.
8. `wxt.config.ts` — build and manifest configuration.
9. `docs/` — the bundled reference documentation.

## Try the extension by hand

Chrome and Edge load an unpacked extension from a folder. With `bun run dev` running, open
`chrome://extensions` (Edge: `edge://extensions`), turn on **Developer mode**, choose
**Load unpacked** and select the `.output/chrome-mv3-dev` folder. WXT rebuilds that folder on
every save and asks the extension to reload; if a change does not show up, press the reload
button on the extension's card. To try a production build instead, run `bun run build` and
load `.output/chrome-mv3`. For Firefox, run `bun run build:firefox`, open `about:debugging`,
choose **This Firefox**, then **Load Temporary Add-on** and select any file in the
`.output/firefox-mv2` folder. WXT opens a browser by itself only if you install the optional
`web-ext` package.

## Publishing

Release steps, store accounts and review rules are in
[`docs/extension/07-publishing-and-stores.md`](docs/extension/07-publishing-and-stores.md).

does not publish to any store.
