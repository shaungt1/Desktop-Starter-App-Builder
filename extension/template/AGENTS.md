# Agent instructions for __APP_NAME__ (browser extension)

These instructions apply to any AI coding agent working in this repository.
Read them fully before making a change.

## What this project is

A Manifest V3 browser extension generated by Desktop Starter App Builder, built
with WXT (the extension build framework), React, Tailwind CSS and TypeScript. It
is a self-contained project with its own Git history; the builder is not needed
to work on it. `project-plan.json` records the decisions it was built from, and
`.desktop-starter.json` records the builder version and the enabled modules.
This extension was generated with the following choices.

| Choice | Value |
| --- | --- |
| Frontend | __FRONTEND__ |
| Interface kit | __UI_KIT__ |
| Package manager | __PACKAGE_MANAGER__ |

`README.md` explains the folder layout. `docs/README.md` indexes the bundled
reference: `docs/SETUP_RESOURCES.md` (tools per operating system) and
`docs/extension/` (architecture, permissions, messaging and storage, content
scripts, testing, browsers, publishing to the stores). Read the relevant page
before changing permissions, adding a content script or preparing a release.

## Before the first change on a new machine

1. Run `bun run doctor`. It checks the tools this project needs and prints the fix for anything missing. It never installs anything.
2. If tools are missing, ask the user before installing. With approval, run `bash scripts/bootstrap.sh --dry-run` (it detects Windows in Git Bash, macOS or Linux; `scripts\bootstrap.ps1` is the PowerShell alternative) to show the plan, then the same command without `--dry-run`.
3. Run `bun install`, then `bun run verify` to confirm a clean baseline before editing anything.

## Commands that prove a change works

Run these from the project root, in this order, and do not report a task as
done until they pass.
1. `bun install` after any change to `package.json`.
2. `bun run verify` — type check (`tsc`), lint and format check (Biome) and unit tests (Vitest).
3. `bun run test:e2e` when the change affects the popup, options page, background worker, content scripts or the manifest. It builds the extension, loads it into Chromium and drives it.
4. `bun run build` and `bun run build:firefox` before a release, to prove both browser builds still work.

To try the extension by hand, run `bun run dev`: WXT builds into `.output/chrome-mv3-dev`
and rebuilds when files change. Load that folder once as an unpacked extension
(`chrome://extensions`, **Developer mode**, **Load unpacked**); the extension then reloads
itself on every rebuild. WXT only opens a browser by itself when the optional `web-ext`
package is installed (`docs/extension/01-architecture-and-project-files.md`).

## Rules

1. **Least privilege.** Every permission and every match pattern is something the user is asked to trust and the store reviewer checks. Add a permission only when a feature needs it, prefer `activeTab` and optional permissions to broad host access, and never use `<all_urls>` or `*://*/*` unless the user explicitly asks and you explain the review and trust cost.
2. **Messages are untrusted.** Every message goes through `src/lib/messaging.ts`, which validates it with Zod before a handler runs. Add new message types to the `messages` object there; do not call `browser.runtime.sendMessage` directly.
3. **The background worker is stopped when idle.** Keep no state in module variables. Save state with the typed items in `src/lib/settings.ts`. Register every event listener synchronously at the top of `defineBackground`, never inside a promise or timer.
4. **No remote code.** Manifest V3 forbids loading and running code from the network. Fetch data, never scripts; bundle everything the extension runs.
5. **No secrets in the extension.** Anything in the package can be read by every user. Call your own backend for secrets, and keep store credentials only in repository secrets.
6. **Content scripts run on pages you do not control.** Treat page content as untrusted: never insert it with `innerHTML`, validate anything read from the page, and keep `matches` as narrow as the feature allows.
7. **Generated files** — `src/modules/registry.ts` and `src/permissions.generated.json` — are rewritten when a module is added with the builder. Put your own permissions in `wxt.config.ts`.
8. **Dependencies.** Use `bun add <pkg>` (or `bun add -d` for tools). Keep the bundle small: every kilobyte is downloaded by every user and counted in review.
9. **Publishing** (store submission, pushing a `v*` tag, running the Release workflow with `submit`) needs explicit approval from the user for each release.

## Where things are

The table below lists the places most tasks touch.

| Task | Where |
| --- | --- |
| Change the toolbar popup | `src/app/popup-screen.tsx` (rendered by `entrypoints/popup/main.tsx`) |
| Change the options page | `src/app/options-screen.tsx` |
| Add a saved setting | A new item in `src/lib/settings.ts`; read it in React with `useStorageItem` |
| Add a message between parts | `messages` in `src/lib/messaging.ts`, a handler in `entrypoints/background.ts`, and `sendMessage` at the call site |
| Run code on web pages | `entrypoints/content.ts` (change `matches`), or a new `entrypoints/<name>.content.ts` |
| Add a permission | `permissions` in `wxt.config.ts`, with the reason in a comment |
| Add a UI component | `src/components/ui/` |
| Add a side panel, context menu or page overlay | `bash start.sh module add <id> <this folder>` in the builder (`side-panel`, `context-menu`, `content-ui`) |
| Change brand colors | `src/styles/globals.css` |
| Change icons | `public/icon/` (16, 32, 48, 96 and 128 px PNG files) |
| Build for another browser | `bun run build:firefox`; Edge uses the Chrome build |
| CI and releases | `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `docs/extension/07-publishing-and-stores.md` |
