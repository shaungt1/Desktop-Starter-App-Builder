# __APP_NAME__

__APP_DESCRIPTION__

This desktop application was generated by Desktop Starter App Builder on the
**Tauri 2** base. Tauri runs the app as a compiled **Rust core** (which owns
the operating system: files, network, windows, tray) and a **web view**
provided by the operating system (WebView2 on Windows, WKWebView on macOS,
WebKitGTK on Linux) that renders the React interface. The interface can only
reach the Rust core through **commands** and **plugins**, and only when a
**capability** file grants the permission. The exact choices used to generate
this app are recorded in `project-plan.json` and `.desktop-starter.json`, and
summarized here.

| Choice | Value |
| --- | --- |
| Frontend | __FRONTEND__ |
| Interface kit | __UI_KIT__ |
| Package manager | __PACKAGE_MANAGER__ |
| Targets | __TARGETS__ |

This folder is a self-contained project with its own Git repository. Its
`docs/` folder holds the full reference for building, testing, signing and
shipping it ([`docs/README.md`](docs/README.md) is the index), so it does not
depend on the builder that created it.

## Requirements

Run `bun run doctor` first: it checks every tool below and prints the fix for
anything missing. `bash scripts/bootstrap.sh` (Windows in Git Bash, macOS,
Linux; it detects which) installs what is missing after showing a plan and asking; add `--dry-run` to
only see the plan. [`docs/SETUP_RESOURCES.md`](docs/SETUP_RESOURCES.md) gives
the manual steps for each operating system. The tools are these.
- **Bun** 1.3 or newer.
- **Rust** stable 1.90 or newer, installed with rustup.
- **Windows:** Microsoft C++ Build Tools ("Desktop development with C++") and the WebView2 runtime (included in Windows 10 1803+ and Windows 11).
- **macOS:** Xcode Command Line Tools (`xcode-select --install`).
- **Linux (Debian/Ubuntu):** `sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev`.

## Everyday commands

Each command below is run from this folder.

| Command                   | What it does                                                                                      |
| ------------------------- | ------------------------------------------------------------------------------------------------- |
| `bun run doctor`          | Checks this machine for the tools this app needs; changes nothing.                                |
| `bun install`             | Installs the interface packages and the Tauri command-line tool.                                  |
| `bun run dev`             | Starts the interface dev server (Vite on 1420, or Next.js on 3000) and the app; Rust changes relaunch.        |
| `bun run verify`          | The quality gate: type check, lint, interface unit tests and Rust unit tests.                     |
| `bun run test:e2e`        | Builds a debug binary and drives it through WebDriver (needs `tauri-driver`; see below).          |
| `bun run build:app`       | Release build and installers into `src-tauri/target/release/bundle/`.                             |
| `bun run tauri <command>` | Any Tauri CLI command, e.g. `bun run tauri add <plugin>` or `bun run tauri icon assets/icon.png`. |

Apps with Android or iOS targets also have `android:init`, `android:dev`,
`android:build`, `ios:init`, `ios:dev` and `ios:build` scripts; run the `init`
script once on a machine with the mobile SDKs before the others
([`docs/tauri/14-mobile.md`](docs/tauri/14-mobile.md)). iOS builds need a Mac.

The first Rust build downloads and compiles all crates and takes noticeably
longer than later builds. `src-tauri/Cargo.lock` pins every crate version;
commit it.

## How the code is organized

The table below maps each path to its responsibility. Files marked
_generated_ are rewritten when a module is added with the builder.

| Path                          | Responsibility                                                                                                      |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `src-tauri/src/lib.rs`        | Start-up: core plugins, enabled modules, the main window and the command handler.                                   |
| `src-tauri/src/window.rs`     | Creates the main window; native profile shows the bundled interface, remote profile a hosted URL.                   |
| `src-tauri/src/commands.rs`   | Commands every app has (`app_info`, `open_external`).                                                               |
| `src-tauri/src/error.rs`      | `AppError`, the one error type commands return; it reaches the interface as a readable message.                     |
| `src-tauri/src/app_config.rs` | Reads `app.config.json` (compiled into the binary).                                                                 |
| `src-tauri/src/modules/`      | One Rust file per module; `mod.rs` (_generated_) registers plugins, start-up hooks and commands.                    |
| `src-tauri/capabilities/`     | Permission grants. `default.json` is the core set; each module adds its own file.                                   |
| `src-tauri/tauri.conf.json`   | Identity, build hooks, security policy (CSP), bundles and plugin settings.                                          |
| `src/`                        | The React interface: `screens/`, `components/` (layout and `ui/`), `features/<id>/` module panels, `lib/ipc.ts` command wrappers, `lib/navigation.tsx`, `lib/app-identity.ts`; `app/` holds the routes with the Next.js frontend. |
| `docs/`                       | Bundled reference: setup per operating system, Tauri plugins, signing, CI, stores, mobile, interface kits.        |
| `scripts/`                    | `doctor.mjs` (machine check), `bootstrap.sh` (install missing tools; Git Bash on Windows) and `bootstrap.ps1` (PowerShell alternative).                          |
| `.github/workflows/`          | `ci.yml` (verify on Windows, macOS, Linux; end-to-end tests on Linux) and `release.yml` (installers to a draft GitHub release on a `v*` tag). |
| `.vscode/`                    | Tasks for every command above and recommended extensions.                                                          |

## Calling Rust from the interface

Commands are Rust functions marked `#[tauri::command]` and listed in
`src-tauri/src/modules/mod.rs` (`generate_handler!`). The interface calls them
through typed wrappers that use `invoke` from `@tauri-apps/api/core`, for
example `ipc.app.info()` in `src/lib/ipc.ts`. Arguments are camelCase in
TypeScript and snake_case in Rust; Tauri converts between them. Commands that
can fail return `AppResult<T>`, which reaches the interface as a rejected
promise carrying the error message.

Plugins work the same way but are also **denied by default**: installing a
plugin does nothing until a capability file lists its permission. A missing
permission shows up at run time as a rejected call naming the permission.

## End-to-end tests

`bun run test:e2e` uses `tauri-driver`, Tauri's WebDriver proxy. Install it
once with `cargo install tauri-driver --locked`. On Linux also install
`webkit2gtk-driver` and run headless with `xvfb-run -a bun run test:e2e`. On
Windows put an `msedgedriver.exe` matching the installed WebView2 version on
your `PATH`. macOS has no native WebDriver for its web view, so these tests run
on Windows and Linux.
