# Agent instructions for __APP_NAME__ (Tauri 2)

These instructions apply to any AI coding agent working in this repository.
Read them fully before making a change.

## What this project is

A Tauri 2 application generated by Desktop Starter App Builder: a Rust core in
`src-tauri/` and a React interface in `src/`. It is a self-contained project
with its own Git history; the builder is not needed to work on it.
`project-plan.json` records the decisions it was built from, and
`.desktop-starter.json` records the builder version and enabled modules. This
app was generated with the following choices.

| Choice | Value |
| --- | --- |
| Frontend | __FRONTEND__ |
| Interface kit | __UI_KIT__ |
| Package manager | __PACKAGE_MANAGER__ |
| Targets | __TARGETS__ |

`README.md` explains the layout. `docs/README.md` indexes the bundled
reference: `docs/SETUP_RESOURCES.md` (tools per operating system),
`docs/tauri/` (configuration, security and capabilities, IPC, every official
plugin with when and why to use it, testing, signing, release pipelines,
distribution and app stores, mobile, Next.js) and `docs/UI_KITS.md`. Read the
relevant page before adding a plugin, changing permissions, or touching
signing, releases or mobile.

## Before the first change on a new machine

1. Run `bun run doctor`. It checks the tools this app needs (including Android/iOS tooling when the targets include them) and prints the fix for anything missing. It never installs anything.
2. If tools are missing, ask the user before installing. With approval, run `bash scripts/bootstrap.sh --dry-run` (it detects Windows in Git Bash, macOS or Linux; `scripts\bootstrap.ps1` is the PowerShell alternative) to show the plan, then the same command without `--dry-run`.
3. Run `bun install`, then `bun run verify` to confirm a clean baseline before editing anything.

## Commands that prove a change works

Run these from the project root, in this order, and do not report a task as
done until they pass.
1. `bun install` after any change to `package.json`.
2. `bun run verify` — TypeScript check, Biome lint and format check, Vitest interface tests and `cargo test`.
3. `bun run test:e2e` when the change affects start-up, windows, commands, permissions, navigation or a module's user flow (Linux: `xvfb-run -a bun run test:e2e`; needs `tauri-driver`, see `docs/tauri/08-testing-debugging.md`).
4. Mobile targets: `bun run android:dev` / `bun run ios:dev` on a machine with the SDKs after `android:init` / `ios:init` (`docs/tauri/14-mobile.md`). WebDriver end-to-end tests do not run on mobile.

## Rules

1. **Permissions are deny-by-default.** A plugin call works only if a file in `src-tauri/capabilities/` grants it. Add the narrowest permission that the error message names; never grant broad sets such as `fs:default` with an unrestricted scope, or `shell:default`.
2. **Prefer a Rust command over exposing a plugin to the interface** when the interface only needs a result (see how the filesystem module opens dialogs from Rust and checks paths).
3. **Every command that can fail returns `AppResult<T>`** (`src-tauri/src/error.rs`). Do not `unwrap()` on user input or I/O.
4. **Commands are generic over the runtime** (`fn name<R: Runtime>(app: AppHandle<R>)`) so the shared handler in `modules/mod.rs` can register them.
5. **Shared mutable state** is registered with `.manage()` and guarded by a lock; do not hold a `std::sync::Mutex` guard across an `.await`.
6. **Generated files** — `src-tauri/src/modules/mod.rs` and `src/features/registry.ts` — are rewritten when a module is added with the builder. For your own commands, add them to `generate_handler!` in `mod.rs` and keep the list sorted by module.
7. **Secrets** never go into `app.config.json`, `tauri.conf.json`, source files or the interface. Use the secure-storage module (`get_secret`/`set_secret` in Rust).
8. **Database changes** are new entries at the end of `migrations()` in `src-tauri/src/modules/database.rs` with the next version. Never edit a shipped migration.
9. **Keep the dev server address in sync.** Vite frontend: `devUrl` port 1420 in `tauri.conf.json` matches `vite.config.ts`. Next.js frontend: `devUrl` is `http://localhost:3000` and `frontendDist` is `../out`. A mismatch is the usual cause of a blank window.
10. **Desktop-only code stays behind `#[cfg(desktop)]`** (window size and title, tray, single instance, window state, updater) so Android and iOS builds compile. Desktop-only plugin crates go under the desktop target in `Cargo.toml` (`docs/tauri/10-plugin-catalog.md` lists which plugins are desktop-only).
11. **Next.js frontend only.** Every route must be exportable to static files: no server actions, route handlers, middleware, `next/image` optimization or dynamic routes without `generateStaticParams`. Call Tauri APIs only from `"use client"` code, inside effects, query functions or event handlers.
12. **Releases, signing and store submission** need explicit approval from the user for each release.

## Where things are

The table below lists the places most tasks touch.

| Task | Where |
| --- | --- |
| Add a screen (Vite frontend) | A component in `src/screens/`, registered in `src/router.tsx`, and a link in `src/components/app-layout.tsx` |
| Add a screen (Next.js frontend) | A component in `src/screens/`, a route file `src/app/<route>/page.tsx` that renders it (`"use client"`), and a link in the layout |
| Navigate in code | `NavLink` and `useAppNavigation()` from `src/lib/navigation.tsx` (works with both frontends) |
| Add a command | A `#[tauri::command]` in `src-tauri/src/commands.rs` or a module file, listed in `generate_handler!`, plus a wrapper in `src/lib/ipc.ts` |
| Add an official plugin | Choose it with `docs/tauri/10-plugin-catalog.md`; `bun run tauri add <name>`, then register it in `lib.rs` or a module and grant its permission in a capability file |
| Background work | Spawn a task in a module `setup` with `tauri::async_runtime::spawn`; stream progress with events or a `Channel` |
| Animation and gestures | `motion/react` and `@use-gesture/react` (see `docs/UI_KITS.md`) |
| Change identity, windows, CSP or bundles | `src-tauri/tauri.conf.json` and `src-tauri/src/window.rs` |
| Icons | `bun run tauri icon path/to/icon.png` (writes every size into `src-tauri/icons/`) |
| Signing, CI and releases | `docs/tauri/11-signing.md`, `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `docs/tauri/12-pipelines-ci.md` |
| App stores and installers | `docs/tauri/13-distribution-stores.md` |
| Change brand colors | `src/styles/globals.css` |
| App name and description shown in the interface | `src/lib/app-identity.ts` |
